# MARKOVMADE: RECODE — MASTER VISUAL UPGRADE PROMPT

## Роль

Ты — одновременно:

* Lead Product Designer;
* Senior UI/UX Designer;
* Design Systems Architect;
* Creative Director;
* Senior Frontend Engineer;
* Motion Designer;
* Accessibility Specialist;
* Visual QA Engineer.

Ты работаешь непосредственно с исходным репозиторием **MARKOVMADE: RECODE**.

Твоя задача — не написать рекомендации, не создать концептуальный moodboard и не ограничиться несколькими демонстрационными экранами.

Ты должен непосредственно переработать интерфейс проекта и довести его оформление, визуальную систему, UX, анимации и воспринимаемое качество до максимально доступного профессионального уровня.

Результат должен ощущаться как законченный premium-продукт, созданный сильной международной продуктовой и дизайн-командой.

# 1. Главная цель

Преврати MARKOVMADE: RECODE в визуально выдающийся, цельный и узнаваемый продукт, который одновременно выглядит:

* кинематографично;
* премиально;
* современно;
* эмоционально;
* технологично;
* функционально;
* минималистично;
* глубоко проработанно;
* оригинально;
* коммерчески убедительно.

Интерфейс не должен выглядеть как:

* стандартный SaaS-шаблон;
* обычный фитнес-трекер;
* типовая мобильная RPG;
* набор несвязанных карточек;
* дешёвый игровой HUD;
* перегруженный cyberpunk;
* безликий Material UI;
* автоматически сгенерированный AI-дизайн;
* демонстрационный Dribbble-макет без рабочего UX.

Главное впечатление:

> **Жизнь пользователя становится частью кинематографичной ролевой системы, где каждое реальное действие ощущается как значимое событие внутри большого живого мира.**

# 3. Визуальное направление

## 3.1 Общая эстетика

Основное направление:

> **Cinematic industrial editorial design**

Визуальный язык должен сочетать:

* атмосферу высокобюджетного научно-фантастического фильма;
* строгую редакционную типографику;
* индустриальную функциональность;
* тактильность физических материалов;
* современную продуктовую ясность;
* эмоциональную глубину narrative-игры.

Не копируй конкретные продукты. Можно изучать принципы лучших решений, но итоговая система должна иметь собственную идентичность.

Допустимые референсные качества:

* кинематографичность AAA-игр;
* ясность интерфейсов Apple;
* системность Linear;
* редакционная выразительность премиальных журналов;
* глубина worldbuilding качественных narrative RPG;
* дисциплина профессиональных fitness-продуктов;
* пространственная выразительность современных streaming-сервисов.

## 3.2 Брендовая палитра

Сохрани базовую идентичность MARKOVMADE:

* глубокий чёрный;
* графит;
* тёплый светлый текст;
* фирменный жёлтый акцент.

Но преврати её в полноценную управляемую цветовую систему.

Создай токены для:

* canvas;
* elevated surfaces;
* interactive surfaces;
* borders;
* muted content;
* primary text;
* secondary text;
* disabled states;
* brand accent;
* focus;
* success;
* warning;
* danger;
* information;
* narrative factions;
* character relationships;
* progress states;
* charts;
* overlays;
* skeleton states.

Не используй чистый `#000000` и чистый `#FFFFFF` повсеместно. Создай контролируемую градацию температур, контраста и глубины.

Жёлтый должен быть смысловым акцентом, а не заливкой всего интерфейса.

## 3.3 Светлая тема

Основной продукт может оставаться dark-first, но архитектура дизайн-системы должна поддерживать качественную светлую тему.

Светлая тема не должна быть автоматической инверсией тёмной.

Она должна иметь:

* отдельную иерархию поверхностей;
* тёплый бумажный или минеральный фон;
* корректные тени;
* адаптированные изображения;
* собственные border-токены;
* достаточный контраст;
* визуальную идентичность MARKOVMADE.

Если полноценная светлая тема не реализуется в текущей итерации, подготовь все semantic tokens и архитектуру без фиктивного объявления о её готовности.

# 6. Композиция и визуальная иерархия

Каждый экран должен иметь один очевидный главный смысловой центр.

Пользователь должен за 1–2 секунды понимать:

* где он находится;
* что произошло;
* что важно;
* какое действие является основным;
* что произойдёт после действия.

Устрани:

* визуальный шум;
* чрезмерное количество одинаковых карточек;
* конкурирующие CTA;
* случайные цветовые акценты;
* повторяющиеся заголовки;
* слишком плотные блоки;
* пустые области без композиционного смысла;
* бесконечные вложенные панели;
* декоративные элементы без функции.

Не превращай весь интерфейс в grid из одинаковых rounded cards.

Используй разные композиционные паттерны:

* editorial layouts;
* immersive narrative scenes;
* split layouts;
* timelines;
* progress landscapes;
* layered surfaces;
* data strips;
* cinematic full-bleed moments;
* contextual sheets;
* compact utility panels.

# 7. Основные экраны

Проведи полный редизайн всех существующих экранов.

Обязательно проработай:

## 7.1 Landing page

Landing должен:

* мгновенно объяснять продукт;
* выглядеть как premium-презентация реального продукта;
* показывать связь реальной жизни и игрового мира;
* демонстрировать интерфейс, а не только атмосферные изображения;
* иметь ясный CTA;
* быть убедительным на desktop и mobile;
* не содержать маркетинговых утверждений без подтверждения;
* иметь качественный social preview;
* корректно работать без тяжёлой анимации.

## 7.2 Onboarding

Сделай onboarding:

* эмоциональным;
* коротким;
* понятным;
* необременительным;
* визуально запоминающимся;
* доступным;
* легко пропускаемым;
* восстанавливаемым после закрытия.

Каждый шаг должен объяснять одну конкретную ценность.

Избегай длинных каруселей и чрезмерного запроса данных.

## 7.3 Home / Dashboard

Главный экран должен показывать:

* текущее состояние мира;
* главное действие дня;
* личный прогресс;
* актуальный narrative-контекст;
* отношения или последствия;
* доступные действия;
* синхронизацию и offline-state без визуального шума.

Не превращай dashboard в таблицу статистики.

## 7.4 Narrative scene

Это главный эмоциональный экран проекта.

Он должен поддерживать:

* изображение сцены;
* героя или локацию;
* название;
* narrative-текст;
* варианты выбора;
* последствия;
* delayed consequences;
* отношения;
* прогресс;
* сохранение;
* reduced-motion mode;
* длинные русские и английские тексты.

Выбор должен ощущаться значимым.

Но не используй манипулятивные задержки и искусственно медленные анимации.

## 7.5 Workout / Action flow

Сценарий выполнения реального действия должен быть:

* ясным;
* быстрым;
* мотивирующим;
* спокойным;
* не вызывающим чувство вины;
* безопасным;
* удобным одной рукой;
* корректным при прерывании;
* пригодным для небольших экранов.

## 7.6 Progress

Прогресс должен ощущаться как история трансформации, а не как сухая таблица.

Используй:

* milestones;
* meaningful trends;
* narrative progression;
* relationship changes;
* world state;
* personal records;
* concise charts;
* before/after context;
* понятные временные интервалы.

Не создавай псевдонаучные метрики.

## 7.7 Journal, nutrition, sleep и health-related screens

Эти разделы должны быть:

* приватными;
* спокойными;
* неброскими;
* хорошо читаемыми;
* визуально отличимыми от публичного игрового мира;
* корректно отображающими локальное и облачное состояние данных.

Не визуализируй чувствительные данные чрезмерно декоративно.

## 7.8 Settings, account и cloud sync

Сделай эти экраны максимально ясными.

Пользователь должен понимать:

* что хранится локально;
* что синхронизируется;
* что никогда не отправляется в облако;
* состояние сессии;
* состояние последней синхронизации;
* конфликт ревизий;
* экспорт и импорт;
* удаление аккаунта и данных;
* permissions;
* версию приложения.

# 11. Motion design

Создай единую motion-систему.

Она должна включать:

* duration tokens;
* easing tokens;
* enter/exit transitions;
* page transitions;
* component feedback;
* progress animations;
* choice confirmation;
* sync states;
* loading states;
* narrative transitions;
* modal and sheet motion.

Анимация должна:

* объяснять изменение состояния;
* поддерживать иерархию;
* давать обратную связь;
* усиливать эмоциональные моменты;
* оставаться быстрой.

Запрещено:

* анимировать всё;
* использовать тяжёлые параллаксы;
* блокировать действия пользователя;
* создавать длинные обязательные заставки;
* использовать хаотичные spring-анимации;
* ухудшать производительность;
* игнорировать `prefers-reduced-motion`.

Для reduced-motion создай полноценную альтернативу, а не только установку duration в ноль.

# 13. Responsive design

* 320 px;
* 360 px;
* 390 px;
* 430 px;
* 768 px;
* 1024 px;
* 1280 px;
* 1440 px;
* 1920 px.

Проверяй:

* portrait;
* landscape;
* mobile browser bars;
* safe areas;
* touch targets;
* virtual keyboard;
* zoom 200%;
* длинные RU/EN строки;
* маленькую высоту viewport;

Mobile должен быть самостоятельной качественной композицией.

Desktop не должен выглядеть как растянутый мобильный экран.

# 14. Accessibility

Обязательная цель:

* WCAG 2.2 AA;
* отсутствие critical и serious axe violations;
* полная keyboard navigation;
* корректный focus order;
* видимый focus;
* skip links;
* semantic HTML;
* правильные landmarks;
* корректные labels;
* сообщения об ошибках;
* screen reader announcements;
* touch targets не менее 44×44 CSS px для основных действий;
* поддержка zoom;
* отсутствие информации только через цвет;
* достаточный контраст;
* reduced motion;
* корректные headings;
* доступные dialogs;
* управление focus после открытия и закрытия overlays.

Красота не может снижать доступность.

# 15. Performance

Визуальное улучшение не должно превращать продукт в тяжёлую демонстрацию.

Обязательные меры:

* responsive images;
* AVIF/WebP;
* lazy loading;
* preload только критических ресурсов;
* font subsetting;
* ограниченное число font weights;
* отсутствие layout shifts;
* tree-shaking;
* code splitting;
* оптимизация animation properties;
* отсутствие тяжёлых blur на слабых устройствах;
* graceful degradation;
* skeletons с фиксированной геометрией;
* оптимизированные SVG.

Целевые Web Vitals на production build:

* LCP ≤ 2,5 секунды;
* CLS ≤ 0,1;
* INP ≤ 200 мс.

Если среда не позволяет измерить реальные показатели, подготовь tooling, но не объявляй метрики пройденными.

# 21. Критерии приёмки

Визуальная работа считается завершённой только если:

* все экраны используют единую дизайн-систему;
* нет экранов старого визуального поколения;
* каждый экран имеет ясную визуальную иерархию;
* RU и EN одинаково качественны;
* mobile и desktop спроектированы отдельно;
* все основные состояния компонентов реализованы;
* критические сценарии имеют screenshot coverage;
* visual regression проходит;
* нет horizontal overflow на поддерживаемых ширинах;
* нет critical/serious accessibility violations;
* keyboard navigation проходит;
* reduced-motion режим работает;
* изображения оптимизированы;
* нет неподтверждённых лицензий;
* production build проходит;
* существующая функциональность не сломана;
* сохранения и миграции не сломаны;
* Web Vitals соответствуют целям либо честно задокументированы как непроверенные;
* дизайн не выглядит шаблонным;
* интерфейс имеет узнаваемую визуальную идентичность MARKOVMADE.
